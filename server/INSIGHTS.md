## What Works
<!-- Approaches and solutions that proved themselves. -->
- **2026-11-27 — Prove atomicity with a raising `BEFORE` trigger, not a mock.** In an `*.it.test.ts`, `CREATE TRIGGER … BEFORE INSERT ON <last table of the flow> … EXECUTE FUNCTION <raise>` makes a real Postgres write fail part-way; assert nothing of the flow is left, then drop the trigger in `afterEach`. Works through the real route/executor with no code seams. (`server/test/transactions.it.test.ts`)

## What Doesn't Work
<!-- Dead ends and antipatterns — always with WHY. Most-skipped, most valuable. -->
- **2026-11-27 — `withTimeout` cannot time out synchronous work.** Don't wrap a sync call as `withTimeout(Promise.resolve().then(() => syncFn()), ms)` expecting a cap, because the sync call runs inside the same microtask drain and the race settles before the timer (a macrotask) can fire; the repo-intel per-file parse "watchdog" was such a no-op and was removed. A real cap needs a worker thread. (`server/src/modules/repo-intel/pipeline/parse-file.ts`)

## Codebase Patterns
<!-- Non-default conventions and architecture decisions. -->
- **2026-11-21 — File rank is PageRank only; `hotness` is always 0 ("Option B").** Don't treat `hotness` as a signal or make it non-zero without first deepening clones, because clones are shallow (`CLONE_DEPTH = 1`) so there is no churn history. (`server/src/modules/repo-intel/pipeline/rank.ts`)
- **2026-11-21 — Run cost comes from the engine, never recompute it.** Use `outcome.costUsd` from `reviewPullRequest` (OpenRouter's real `usage.cost`, else the PriceBook estimate) when persisting `agent_runs.cost_usd`, because recomputing tokens × price would diverge from the OpenRouter dashboard; failed/cancelled runs write `null`, not 0. (`server/src/modules/reviews/run-executor.ts`)
- **2026-11-21 — `setupRepoAndPr` always creates PR #482 in a fresh repo.** Change the second PR's `number` before moving it into the same repo in a test, because `pull_requests` is unique on (repo_id, number). (`server/test/reviews.it.test.ts`)
- **2026-11-21 — PR list findings = briefs of the latest `kind='review'` review.** Take `latest_findings` from the same newest review that gives the list its score (one extra `IN` query on `findings`), shaped by `toFindingBrief`/`sortBriefs`; `rollupSeverities` in the same file is an unused leftover, because counts are derived client-side from the briefs. (`server/src/modules/pulls/status.ts`, `server/src/modules/pulls/routes.ts`)
- **2026-11-26 — A job that times out is failed, not retried.** Don't assume `JobRunner` retries overlap after a timeout: `withRetry`'s default `isRetryable` only retries 429/5xx/`ECONNRESET`-style errors and `TimeoutError` has neither, while `withTimeout` only races (the handler keeps running). Add an `AbortSignal` if a job must really stop. (`server/src/platform/resilience.ts`, `server/src/platform/jobs.ts`)
- **2026-11-27 — Repositories take `DbOrTx`; cross-repository atomicity goes through a per-module `UnitOfWork` port.** The port lives in `<m>/ports.ts`, the generic `DrizzleUnitOfWork` in `db/unit-of-work.ts`, the getter in the container (`reviewsUow`). A repository may still wrap its own aggregate's writes in `this.db.transaction` (becomes a savepoint inside a UoW), e.g. agent version bumps lock the row with `.for('update')`. (`server/src/db/unit-of-work.ts`, `server/src/modules/agents/repository.ts`)
- **2026-11-27 — `container.agentsRepo` is an `AgentsPort` returning the shared `Agent` DTO (snake_case), not `AgentRow`.** Read `agent.system_prompt` / `ci_fail_on` / `repo_intel` in reviews code; the row → DTO mapping (`toAgentDto`, `toAgentVersionDto` with `AgentVersionConfig.parse`) runs inside `AgentsRepository`. Job handlers are registered in `app.ts` `registerJobHandlers` (clone), not in route plugins (repo-intel's still are). (`server/src/modules/agents/ports.ts`, `server/src/app.ts`)
- **2026-11-27 — Reviews code works on `ReviewPull` / `ReviewRecord` / `FindingRecord`, wired by `createReviewService(container)`.** `container.reviewRepo` is a `ReviewStore` (reviews ports + pulls' `ReviewSummaryPort`/`RunCostsPort`); rows are mapped in `reviews/repository/mappers.ts`. Build `ReviewService`/`ReviewRunExecutor` through `createReviewService` (`reviews/routes.ts`, also used by the boot reaper in `app.ts`), because git and the repo-intel facade are passed as lazy `() =>` getters to keep construction timing. Executor tests need a real `new RunBus()` (class with private state), not an object fake. (`server/src/modules/reviews/ports.ts`, `server/test/reviews-service.test.ts`)
- **2026-11-27 — Supersedes "`container.agentsRepo` is an `AgentsPort`…" (2026-11-27) on job handlers:** repo-intel's INDEX/REFRESH/RESYNC handlers are now registered in `app.ts` too, via `registerRepoIntelJobHandlers(container.jobs, () => container.repoIndexer)`. Keep them on `container.repoIndexer`, not `container.repoIntel`, because tests swap the facade with `overrides.repoIntel` and jobs must still index with the real pipeline. (`server/src/modules/repo-intel/indexing.ts`, `server/src/app.ts`)
- **2026-11-27 — `buildApp` reaps every `running` agent run on boot, in every test that builds an app.** Re-set a fixture run to `running` after `buildApp` when a test needs one in flight (e.g. cancel/ownership tests), because rows inserted in `beforeAll` are flipped to `failed` by the next app's reaper. (`server/src/app.ts`, `server/test/contracts-access.it.test.ts`)
- **2026-11-27 — The seed writes skills and links directly, bypassing the skills service's trust rule.** Seeded `community`/`imported_file` skills keep the `enabled` flag from `seed-skills.ts` (e.g. `secret-leakage-gate` is enabled) because the seed inserts rows itself; links go to `agent_skills` without an agent version bump and only when the agent has no links yet, so a re-seed never overwrites a user's Skills tab. Keep `seed-data.test.ts` green: it checks every seeded skill against `CreateSkillRequest` and every built-in prompt against `docs/agent-prompts/*.md`. (`server/src/db/seed.ts`, `server/src/db/seed-skills.ts`)

## Tool & Library Notes
<!-- Dependency quirks, with library + version. -->
- **2026-11-21 — Use `doublePrecision` for USD columns, not `numeric`.** drizzle-orm 0.45 maps Postgres `numeric` to a JS `string` by default, which would leak strings into `z.number()` contracts; `agent_runs.cost_usd` is `doublePrecision` for that reason. (`server/src/db/schema/runs.ts`)

- **2026-11-26 — Tests are never type-checked.** Type-check new test files with a temporary `tsconfig` in `server/` that extends `tsconfig.json` and includes your test file, because `pnpm typecheck` includes only `src/**/*.ts`, Vitest strips types, and `test/` already has 15 latent TS errors (so including all of `test/` fails). (`server/tsconfig.json`)
- **2026-11-26 — Supersedes "Tests are never type-checked" (2026-11-26):** `test/` now has 0 type errors; run `pnpm exec tsc --noEmit -p tsconfig.test.json` (src + test). CI `server-unit` runs it, so no temporary tsconfig is needed. (`server/tsconfig.test.json`)
- **2026-11-27 — drizzle-orm 0.45 wraps driver errors: `err.message` is `Failed query: <sql>\nparams: <all params>`.** The Postgres message is on `err.cause`. Don't persist or show `err.message` of a failed write as-is: `run-executor` stores it in `agent_runs.error`, so a failed trace write saves the whole prompt/trace JSON there. (`server/src/modules/reviews/run-executor.ts`)
- **2026-11-27 — Batched upsert in drizzle-orm 0.45: `onConflictDoUpdate({ set: { col: sql`excluded.<snake_col>` } })`, and dedupe the conflict key first.** A literal in `set` would write the same value to every row; a key repeated in one `values([...])` fails with `ON CONFLICT DO UPDATE command cannot affect row a second time`. (`server/src/modules/pulls/repository.ts`, `server/src/modules/settings/repository.ts`)
- **2026-11-27 — Supersedes "drizzle-orm 0.45 wraps driver errors" (2026-11-27):** `DrizzleUnitOfWork.run` now rethrows a `DrizzleQueryError` (exported from `drizzle-orm`) as `PersistenceError` (short message, driver error on `cause`), so `agent_runs.error` holds `Database write failed (details in the server log)` and the executor logs `err.cause`. Writes outside a unit of work (e.g. `getPrFiles` in the diff fallback) still surface the raw drizzle message. (`server/src/db/unit-of-work.ts`, `server/src/modules/reviews/run-executor.ts`)
- **2026-11-27 — fastify-type-provider-zod 4.0.2's `serializerCompiler` parses the body, then `JSON.stringify(result.data)`.** A `schema.response` therefore drops keys the contract doesn't list, fills `.default()`s and reorders keys to the schema's order; a mismatch throws `ResponseSerializationError` → generic 500. Don't add one where the body can carry more than the contract (raw `Settings` bag, stored `RunTrace` jsonb); to check a route, wrap the compiler and compare `JSON.parse` of input vs output while running the suites. (`server/src/app.ts`)
- **2026-11-27 — Three source files contain a literal NUL byte (dedupe-key separators).** `grep` reports them as binary and silently skips line matches: use `grep -a`; the Read tool warns and Edit/Write refuse them, so edit them with a script that keeps the bytes. Files: `src/adapters/depgraph/index.ts`, `src/modules/repo-intel/pipeline/repo-map.ts`, `src/platform/model-router.ts`.
- **2026-11-27 — Supersedes "Three source files contain a literal NUL byte" (2026-11-27):** the separators are now written as the `\0` escape (same runtime string), so the files are plain text again. Write `\0`, never a raw NUL, in new code. (`src/adapters/depgraph/index.ts`, `src/modules/repo-intel/pipeline/repo-map.ts`, `src/platform/model-router.ts`)
